# 前端来源与边界

统一工作台的导航、页面、请求客户端与图表封装为 LakeEquity 新实现。

`vendor/lightweight-charts.standalone.production.js` 和 `vendor/echarts.min.js` 是本地第三方图表资产，许可证随项目来源清单保留。

`vendor/chart_markers.js`、`vendor/wyckoff_markers.js`、`vendor/ict_markers.js`、`vendor/chart_evidence.js` 复用自 CKHquant_studio 的 `app/my_strategy/web_dashboard/static/js` 工作树。原实现的确认时间、周期投影、来源身份与证据资格核验保留；`core/charts.js` 仅封装展示生命周期，不重新定义算法。

新界面仅通过 `/api/v1` 读取数据、提交任务、重开历史账本和核验预测图。数据运维、模型训练、模型版本、选股和回测均在统一工作台内完成；不启动或嵌入旧控制台。

页面没有内置样例行情、模拟绩效或自动推理。目录、行数、覆盖、模型和任务状态都来自实际 API。无记录与接口错误保留为空或错误状态。

模型中心使用同一多因子训练表单管理 Ridge、LightGBM 和均线多因子 MLP，默认 43 项配置特征；Kronos 是独立预测视图。冻结模型 ID 在模型卡、关注池、模型选股与固定回测间显式传递，滚动回测使用单独的序列 ID。扫描列表对完整后端结果分页，不截取固定前 200 行。数据运维执行前展示白名单范围、预览和确认项；存储清除仅在后端明确启用统一引用保护后提供，必须基于核验计划的精确对象和字节范围，并由用户确认维护条件；能力未启用时只展示核验。

训练范围支持显式股票池或全市场冻结人口；预检与训练都通过新合同返回完整检查范围。最终重拟合是用户从已保存实验显式提交的独立任务，不改写原 OOS 报告或滚动序列；新冻结推理版本不拥有独立 OOS 成绩。

数据检查按需读取 `/api/v1/data` 的数据集结构、完整分页分区与日期、来源汇总与时间序列、质量明细、采集运行和覆盖图。覆盖图保留月度、年度等原始粒度，分区覆盖不被解释为逐日观测完整。数据读取显式选择复权方式与可得时间模式，默认严格历史可知；缺少相应证据时由服务明确拒绝或返回凭证原因。
