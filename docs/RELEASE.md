# 公开发行

本仓库公开当前 LakeEquity 程序源码、冻结计算依赖和必要原生 wheel。自有代码采用 MIT；第三方保留原许可证及 NOTICE。首次安装使用空运行目录，数据和模型资产需要使用者另行合法准备。

## 包内容与来源

发布脚本使用文件白名单，包含当前 `src/`、`frontend/`、隔离测试、公开文档、安装入口以及经过原清单 SHA 核验的冻结依赖子集。不会复制运行目录、虚拟环境、本机配置、原始行情、训练权重、账户、个人审计或迁移记录。上游源码中的交易日历、CA 证书、合同和其他运行资源保留原始来源身份；它们不是用户的运行数据库。冻结上游测试与历史文档经逐文件审阅后外部归档，不作为运行依赖。

绑定开发机冻结证据的历史补采、迁移和日历修复脚本不作为公开安装工具，对应三份维护测试也不分发。当前 Dashboard 中的数据运维接口及其隔离合成测试保留。完整本机维护验收与公开包测试分别记录，不能将前者冒充空安装验收。

`docs/provenance/sources.json` 记录来源版本、输入清单摘要、原文件数量及本次分发数量。历史研究文档和私有迁移证明未分发；公开子集不冒充完整原工作树。研究依赖中经过审阅的本地修改由 `docs/provenance/local_patches.json` 单独声明原始与当前 SHA-256，核验时两者均须精确匹配。经审阅删除的冻结文件由 `docs/provenance/local_omissions.json` 逐项声明原始 SHA-256 和理由；只有精确登记且本地确实缺失的文件才允许略过，未声明缺失、哈希不符、路径越界或文件仍存在都会失败。原冻结来源清单、CZSC 来源清单和原生 wheel 保持原始字节。补充许可位于独立 `third_party/czsc/`。

README 使用的四张既有界面截图及来源说明位于 `docs/assets/`，随源码公开分发。截图中的覆盖和结果属于开发期界面快照。流水线与研究说明从 `docs/public/` 的公开版本导出，包内位于 `docs/`；本机原始历史文档不覆盖、不分发。

`release-manifest.json` 记录除自身外每个公开文件的相对路径、大小和 SHA-256。安装与 `lake.bat verify-sources` 核验该清单；它验证包内一致性，不替代对发布者、GitHub 提交及下载渠道的信任。

## 重新打包

使用 Python 3.12，在项目目录运行：

```powershell
py -3.12 scripts/prepare_release.py --version 0.3.0 --output var/releases/new-build
```

目标必须不存在。输出包含 `repo/` 公开目录、`LakeEquity-v0.3.0-source.zip` 和 `SHA256SUMS.txt`。脚本不修改既有运行状态、服务或 Git 历史。ZIP 时间戳和文件顺序固定，相同输入产生相同 ZIP 字节。发布前需再次检查内容和许可，然后用相同产物完成验证和上传。

## 发行产物保留

发行目录至少保留当前正式发布及一份已验证回滚的 ZIP、SHA 校验和与发布报告；目录名中的 `final`、`publish` 或 `review` 本身不代表发布身份，必须以发布报告中的资产 SHA-256 为准。`repo/` 是验收用解包副本，只有在与保留 ZIP 全文逐文件核对后，才可清理其中的重复文件；`.git`、本地配置、验收生成物及其他 ZIP 外文件不能用整目录删除一并处理。

中间构建、下载验证副本和历史验证输出不设自动删除。维护时按精确路径、文件身份、SHA 和实际分配空间单独审核；唯一验收、许可、研究和变更前证据继续保留。该规则只覆盖发行产物，不授权清理业务数据、模型、账户、输入快照或运行环境。

## 本版验证范围

Windows x64、Python 3.12 下，已从公开源码 ZIP 在独立空目录和全新 `.venv` 完成生产锁、CPU Torch、原生 wheel、CNEquity 与 LakeEquity 安装；`pip check`、来源校验、脱离原宿主路径的源码导入、空配置创建和应用构造通过。网络不稳定时，SnowNLP、DuckDB 和 CPU Torch 使用已按官方索引 SHA-256 核验的 wheel 预置，随后仍执行完整安装器。空安装 `doctor` 为预期的 `partial`，因为公开包不含原始数据库、用户交易日历和 Kronos 资产；不能以开发机数据代替这些检查。

本次未验证另一台全新机器或 Linux/macOS 安装。独立 Qlib 环境为可选安装；依赖锁针对 Windows。未附带的数据和模型资产不能用历史开发机结果代替新安装证据。软件发行不授予模型收益、纸上账户或严格历史研究资格。

## 版本身份与验收入口

安装器在安装前核对 `pyproject.toml`、包内版本和可选发行清单，安装后通过目标解释器检查实际导入版本与安装元数据；不一致时安装失败并说明原因。发行请求的版本必须与源码一致，生成的 `.egg-info/.dist-info` 不进入公开源码包。更新 editable 工作树后，需要重新安装当前项目才能刷新安装元数据；`doctor` 会明确报告此类漂移。

PEP 660 安装可能只刷新虚拟环境的 dist-info，留下会被 `run.py` 优先读取的陈旧源码 egg-info。安装器使用标准构建命令重新生成该元数据，并按入口的 `src` 优先顺序做安装后检查；不手工改写版本字段。

`scripts/validate_http.py` 默认只读检查当前 v1 接口，完成报告区分已检查项与未请求的扫描/回测。只有显式 `--run-jobs` 并指定小股票池及不超过31个自然日的区间，才提交冻结方法的受控验收任务；不会训练或切换发布。即使请求失败，也保存任务身份、错误和结束报告。

`scripts/validate_browser.mjs` 使用已有 Playwright 和 Chromium；`--help` 说明如何指定模块、浏览器、服务地址和输出位置。它检查9个桌面/移动主页面、报告恢复、关注池预检、慢响应、导航取消与搜索空态，拦截业务写入。缺少私有测试记录会显式标为未覆盖，缺少浏览器运行时则失败，不会把它们当成完整通过。

完整本机测试中的冻结日历证据用例默认明确跳过；设置 `LAKE_EQUITY_TEST_LOCAL_EVIDENCE=1` 才启用该集成检查。启用后证据缺失或校验不符仍会失败；不依赖本机历史记录的合成日历测试照常执行。
